# Starter issues to publish

Create these in the GitHub issue tracker after adding the `good first issue` and `help wanted` labels.

| Label | Title | Scope |
| --- | --- | --- |
| `good first issue` | Improve empty-state UI | Review empty states in Library, Liked Songs, playlists, Recents, and search. Make the copy helpful and visually consistent. |
| `good first issue` | Add loading animation polish | Improve loading feedback for search, home shelves, and collection pages without blocking interaction. |
| `good first issue` | Improve README troubleshooting | Add concise troubleshooting steps for Firebase setup, sign-in, notifications, and playback Health checks. |
| `good first issue` | Fix a small UI issue | Pick a reproducible spacing, truncation, or content-description problem and submit a focused fix with a screenshot. |
| `help wanted` | Improve playlist management | Propose and implement one small playlist usability improvement, such as rename flow, cover treatment, sorting, or duplicate feedback. |
| `help wanted` | Improve Android player UX | Improve one player interaction with device verification, such as queue accessibility, buffering feedback, Bluetooth behavior, or notification controls. |

Each published issue should include reproduction or acceptance criteria, affected screen(s), and a note that contributors should comment before beginning work.
